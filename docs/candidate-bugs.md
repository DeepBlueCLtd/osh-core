# osh-core: candidate bugs for maintainer review

**Purpose.** We would like to volunteer fixes for the issues below. Before starting, we'd like the
maintainers to tell us which ones they agree are bugs, and whether the proposed fix is acceptable.
Please mark each row **Endorse** / **Not a bug** / **Fix differently** (with a note), or reply with the
numbers.

**How these were found.**
- We read the source code systematically while writing source-derived documentation.
- Each candidate was then independently re-checked against the code by a separate reviewer, who tried to
  disprove it: searching all modules for callers, overrides, `ServiceLoader`/OSGi registration and tests.
- Items that could not be shown from the code were dropped.
- None of these items has been reproduced at runtime. Each one is backed by a code-path trace, and none is
  covered by an existing test.
- "Confirm intent" marks behaviour that may be deliberate.

**Code version.** Commit `15feef0` (`15feef0e270d8f6d7d01d2f22b86302695c83d95`), reviewed 2026-11-25. Line
links point to that commit in our fork, DeepBlueCLtd/osh-core, which has no source changes from upstream.

**Severity.**
- **High:** wrong results, a hang, a startup failure, or a security bypass on a normal path.
- **Medium:** a feature broken, or misleading, on a reachable path.
- **Low:** an edge case, or a public API path with no caller in this repo.

## Proposed way of working

1. The maintainers mark which items they endorse, and any preferred alternative fix.
2. We open one small PR per endorsed item, or per tightly related group (e.g. #3 + #11, #13 + #14, #18 + #26),
   each with a regression test where the code is testable.
3. Items marked *Confirm intent* will not be changed without explicit agreement.
